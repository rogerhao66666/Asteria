# Golden asset suite

This folder implements ASTERIA_ASSET_SPEC §34, the minimum golden suite:

```text
golden_character  golden_npc  golden_monster  golden_tileset  golden_prop  golden_icon
golden_vfx        golden_projectile  golden_skill  golden_ui  golden_scene
```

`tests/golden/test_golden_assets.py` runs the eight required checks on every asset. The logic lives in `asteria.validation.golden`:

| # | Check | How it is verified |
|---|---|---|
| 1 | Import succeeds | The whole folder loads through `AssetStore` with the engine's typed codecs and validators. |
| 2 | Metadata parses | Manifest fields decode, and each payload round-trips (encode, then decode, gives an equal asset). |
| 3 | Dimensions match | Every image exists. Each sprite or tileset is a whole grid of its frame size. Prop and UI images match their declared sizes. |
| 4 | Assets reload | A second, independent load produces identical assets. |
| 5 | Runtime resolves references | Manifest dependencies resolve, and payload references (character, VFX, icon, projectile, scene placements) are declared dependencies. Sprites build the runtime `SpriteSheet` and `AnimationClipSet`. |
| 6 | Animations play | Every clip, including animated tiles, is played at 60 Hz, and its frame sequence is recorded. |
| 7 | Events fire | Keyframe events and skill beats fire in order; the timed event log is recorded. |
| 8 | Scene packages correctly | `golden_scene` and its dependency closure are copied with `asteria.assets.asset_package` and reload cleanly. |

The suite also compares the recorded results with `baselines/golden_summary.json`. That file holds the kinds, dependencies, image sizes and SHA-256 hashes, frame sequences, event logs, skill beat times and the scene package file list. Any change to an image, timing or event therefore shows up as a baseline diff.

## Reproducible data

`assets/` is generated by `python scripts/build_golden_assets.py`. The build is deterministic and uses only files already in the repository:

- CC0 sheets from `reference_projects/complex_reference_rpg/playable_assets` (Ninja Adventure, Kenney);
- procedurally drawn tiles, a projectile orb and a UI panel.

The documents are written by the engine's own codecs. Do not edit `assets/` by hand; change the build script and rebuild.

## Updating baselines

The baseline is updated only by `python scripts/update_golden_baselines.py`. That script refuses to write while any of the eight checks fails.

Rules:

1. A failing golden test is a regression until proven otherwise. Investigate first; never update the baseline to make a red test green.
2. Update only when the change is intended: a new or changed golden asset, a codec format change, or a deliberate timing or event change.
3. Review the full `git diff` of `golden_summary.json` and check the changed images visually.
4. Commit the asset or script change and the baseline together. The commit message must say why each changed field changed.
5. Removing a golden category, or dropping one of the eight checks, needs an explicit decision in `docs/audits/DECISION_LOG.md`.

## Regression and presentation timing

`baselines/regression.json` holds these values (`asteria.validation.regression`):

- the result of a scripted reference boss battle with a fixed seed: winner, action count, a digest of the battle log, and every combatant's final HP;
- digests of the reference saves;
- the RPG database digest;
- the golden summary digest.

`scripts/update_golden_baselines.py` writes it together with the golden baseline, under the same rules.

`tests/golden/test_regression_and_timing.py` checks presentation timing with `asteria.validation.presentation_timing`. It plays a skill on the canonical battle screen at 30, 60 and 144 fps and with a jittery frame time. The attack pose, effect, hit pose, damage number and hit sound must each appear at the first frame boundary at or after their authored beat.
