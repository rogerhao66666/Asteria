# 遊戲畫面版面計畫 V1–V6（2026-10-25；已核准並完成：V1–V4、V6 見 D76，V5 見 D77）

U1–U6 讓 26 個**選單**畫面都能在編輯器改。這份計畫把剩下四塊**遊戲中**的畫面也接上同一套版面系統：

- 動作 RPG 的 HUD
- 對話框
- 戰鬥畫面
- 生物戰鬥與開始選單

## 現況（2026-10-25 查的）

| 畫面 | 現在怎麼畫 | 作者能改什麼 | 在哪裡改 |
|---|---|---|---|
| 動作 RPG HUD（`runtime/hud_bottom.py`、`action_play.py`） | 程式算位置：左右兩顆球、中間技能列（含按鍵帽、冷卻、消耗）、經驗條、狀態格、其他資源條、上方操作提示、鎖定目標框、大字橫幅、倒地遮罩 | 幾乎不能改，顏色由資源名稱猜 | 沒有 |
| 對話框（`playtest/field_ui.py`） | 預設是程式畫的面板；另有「圖片視窗」模式（視窗圖、文字區、行高、點陣字、顏色、速度、箭頭動畫、選項框） | 頭像樣式與大小（Message Settings）；圖片視窗的設定都有 | 圖片視窗只能寫在遊戲資料夾的 `playable_test_manifest.json`，編輯器改不到 |
| 戰鬥畫面（`presentation/battle_ui*.py`、`battle_hud.py`） | 虛擬 320×180 畫布；HUD 欄位、指令選單、時間軸、結果面板 | 主題顏色、九宮格外框、字型；版面設定只有數字（面板寬、列高、指令選單放上或下、隊伍 HUD 樣式） | 編輯器的戰鬥演出頁；不能拖曳 |
| 生物戰鬥（`runtime/creature_battle.py`）與開始選單（`creature_menu.py`） | 240×160 畫布，整數倍放大；所有圖片可替換；`LAYOUT` 點位與 `COLOURS` 可移動或改色；背包分頁、選項、訓練家卡片的位置都可設定 | 很多 | 全部只在 manifest JSON 裡，編輯器改不到 |

## 原則（沿用 U 計畫）

1. 長相全部是專案資料，在編輯器改；引擎只管邏輯。
2. 每個放圖的欄位都接受任何匯入的檔案（見最後一節「手繪素材」）。
3. **沒有設定版面的專案，畫面逐像素不變。** 照 D60／U2 的做法，每個畫面做逐像素比對。
4. 不寫死玩法：球的數量、技能列格數、指令選單有幾項，都依專案資料決定。
5. 每幀時間不能變慢。戰鬥 HUD 的「只在變化時重排」（D48）要保留；用 `menu_frame_time_check.py` 的方式量。
6. **所有設定都在 GUI 裡改，不用寫 JSON（使用者 2026-10-25 決定）。** 作者用的是編輯器，不是 JSON。
   - 這份計畫裡的每個欄位、圖片、位置、顏色、字元表都要有編輯器畫面可以改。
   - JSON 只是存檔格式，作者不必打開。
   - 現在只能寫在 manifest 的設定，都要搬進專案資料並做成編輯器頁面。

## V1：共用基礎

- **把 `MenuCanvas` 推廣到遊戲中畫面。** 新增幾種畫面 id，版面資料格式不變：
  - `hud.action`
  - `dialogue`、`dialogue.choice`
  - `battle`
  - `creature.battle`、`creature.menu.*`
- **低解析度畫布：** 生物畫面是 240×160 再放大。版面座標用該畫面自己的解析度；編輯器畫布照比例放大，格線對齊原始像素。
- **動畫條欄位：** 一張圖裡上下或左右排著好幾格，加上格數、方向、每秒幾格。給箭頭、寶貝球、技能冷卻、手繪動畫用。
- **點陣字：** `MenuTheme` 和每個元件可以選「點陣字」：一張字圖、每格大小、每一列有哪些字，字圖裡沒有的字自動改用系統字型。
  - 這些全在編輯器的點陣字頁設定：匯入字圖後在格子上逐列打字，旁邊即時預覽一句話。
  - 不用寫 JSON。
- **編輯器預覽：** 「版面」頁的畫面清單加入這些畫面，每個都用範例資料畫出來（照 `menu_preview` 的做法），可拖曳、縮放、換圖。

## V2：對話框

- `dialogue` 版面的元件：
  - 視窗（九宮格或整張圖）、文字區、名字框
  - 頭像位置（臉在左右、半身像）
  - 「下一句」箭頭（動畫條）
  - 選項框、選中游標
- 欄位：行高、字型或點陣字、字色與陰影色、打字速度（依設定裡的文字速度）、每行字數上限。
- manifest 的 `dialogue.window` 設定搬進專案資料，全部在編輯器改。舊專案的 manifest 照樣能讀，編輯器裡一鍵轉成專案資料。
- 驗收：Full Verification 預設不變；另做一個用圖片視窗與點陣字的範例，中英文都截圖。

## V3：動作 RPG 的 HUD

- `hud.action` 元件：
  - 生命球、第二資源球：外框圖、填滿圖、空的圖、數字位置，可改成橫條
  - 技能列底板、技能格：大小、間距、主要格放大、按鍵帽、冷卻遮罩、次數徽章、消耗文字
  - 經驗條、狀態格（好壞兩種外框）、其他資源條
  - 操作提示、鎖定目標框、橫幅文字、倒地遮罩
- 資源顏色可以逐項指定。現在的「看名字猜顏色」保留為預設。
- 驗收：ARPG 範本與 Diablo demo 預設逐像素不變；另做一套換圖的範例。

## V4：戰鬥畫面

- `battle` 元件：
  - 我方 HUD 欄（每位成員的面板、名字、HP／MP 條、狀態圖示）、敵人頭上血條
  - 指令選單（位置、列高、選中外框）、技能／道具清單、說明列
  - 時間軸、訊息列、目標游標、結果面板
- 這些建在現在的 `BattleUiLayoutProfile` 上：原本的數字設定照用，版面只負責移動、縮放、換圖、隱藏。
- 戰場站位（隊伍在左右、地面高度）維持戰鬥演出頁的設定，不在這次範圍。
- 驗收：Full Verification 與 ARPG 範本戰鬥預設逐像素不變，戰鬥每幀時間不變；中英文截圖。

## V5：生物戰鬥與開始選單

- 把 manifest 的 `battle.creature_screen` 與 `field.creature_menu` 改成專案資料：
  - 圖片、`LAYOUT` 點位、`COLOURS`
  - 背包分頁、選項、訓練家卡片、圖鑑、存檔資訊框的位置
- 編輯器裡這些位置都能拖曳，圖片都能換。背包分頁、選項清單、徽章、圖鑑資料用表格編輯，不用寫 JSON。
- manifest 仍可讀（AsteriaEmerald 現在用它），編輯器裡一鍵轉成專案資料。
- **共用檔案：** 這兩個檔案是寶可夢 session 寫的，還在發展中。建議 V5 最後做，開工前先和那個 session 協調，或交給那個 session 做（見「要你決定的事」第 3 點）。

## V6：全面驗收

- 每個新畫面中英文真實視窗截圖；編輯器每個新頁面中英文截圖。
- 逐像素比對：Full Verification、ARPG 範本、生物戰鬥測試專案，沒設版面時畫面不變。
- 每幀時間：HUD、對話、戰鬥、生物畫面都量。
- DECISION_LOG、HANDBOOK、覆蓋文件，附六段式報告。

## 手繪素材（作者自己畫、自己匯入）

使用者 2026-10-25 的要求：不只人物，**任何介面、任何圖示**都要能換成作者手繪的圖，例如技能樹。

**已經可以的（查過的）：**
- 選單版面的每個圖片欄位都有「選擇檔案」：任何 PNG 會複製進專案再使用（`import_ui_file`）；字型 TTF／OTF、音效 OGG 也一樣。
- 九宮格外框：設四邊寬度，有預覽線；像素放大倍數可設（手繪像素圖常用 2× 或 3×）。
- 遊戲資料表單裡的 `icon_id` 欄位（技能、道具、狀態等）是圖示挑選器，可以「瀏覽」自己的檔案，會複製到專案的 `icons/`（`IconLibrary.import_file`）。
- 技能樹節點有自己的 `icon_id`；空白時用它給的第一個技能的圖示。

**這份計畫補上的：**
- **V1 全介面圖示盤點。** 列出引擎在畫面上畫的每一種圖或圖示，每一種都要有編輯器欄位可以換成匯入的檔案。範圍包括：
  - 技能樹：節點框、鎖住／可學／已學三種狀態、連線、點數圖示
  - 狀態圖示、屬性圖示、貨幣圖示、稀有度外框
  - 裝備部位剪影、按鍵帽、選單游標、暫停選單的項目圖示
  - 任務與地圖標記、對話箭頭、HP／MP 條
  - 現在用程式畫的部分改成「預設圖」，作者可以覆蓋。
- **一個自動測試：** 掃過編輯器裡所有圖片和圖示欄位，每一個都要有「選擇檔案」或「瀏覽」。以後新增的欄位漏了，測試就會失敗。
- V1：動畫條（手繪的多格動畫）。
- V1：點陣字（手繪字型），在編輯器裡設定。
- V2–V5：剩下四塊畫面的每張圖都能匯入自己的檔案。

**還要確認的：** 角色行走圖、戰鬥角色圖、地圖圖塊有各自的匯入方式，V1 盤點時一起檢查「能不能只靠 GUI 匯入手繪圖」。缺的列進報告，再決定要不要補。

## 要你決定的事

1. **順序。**
   - **建議：** V1 → V2 → V3 → V4 → V5 → V6，每段結束交截圖和報告。
   - 另一個選項：先做你最想要的那塊。
2. **戰鬥畫面要多自由。**
   - **建議：** 現有元件可以移動、縮放、換圖、隱藏，再加作者自己的裝飾元件，戰鬥邏輯不動。
   - 另一個選項：完全自由排版，連指令選單的形狀（例如環形選單）都可換。這要大改戰鬥 UI，風險高。
3. **生物畫面（V5）誰做。**
   - **建議：** 等寶可夢 session 這輪結束後由我做，manifest 繼續可讀。
   - 另一個選項：交給寶可夢 session，它最熟這兩個檔案。
